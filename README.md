# 暨南大学网络服务小组签到与月报

> 面向 **Windows 10/11 共用电脑** 的本地 Electron 桌面应用。日常签到与月报无需联网；仅检查 GitHub Release 更新时需要网络。不依赖 Node.js、Python 或 Office。

```
平台     Windows 10/11 x64（NSIS 安装包）        运行时    Electron + React + TypeScript
本地存储  SQLite                             版本      0.5.0
协议     MIT 开源
```

---

## 它解决什么问题

暨南大学网络服务小组日常使用一台共用的 Windows 电脑：每天需要记录谁到岗、每人贡献了多少工时；月底要把这些整理成工作报表、绩效考核表、工时记录表、排班表和工资考核表五类正式文件。

这套软件把「每天签到」和「月底导出」放进同一个离线工作区：

- **日常**：打开软件，勾选实际到场人员签到即可，自动按班次累计工时、判断到岗/迟到。
- **月底**：在同一界面核对工时、补填文字与评分，预览后一次性导出五类正式文件。
- **数据是你们的**：签到、排班、备份都只存在本机 SQLite 里；只有启用或手动执行更新检查时访问 GitHub Release。

## 功能特性

- **今日签到首页**：展示当天全部班次、负责人、班次状态与当前班次结束倒计时。
- **签到规则**：只签到、不签退；`开始 ≤ 打卡 < 结束` 计完整班次分钟数；多人维修班分次签到；临时替班与重叠班独立计薪。
- **签到纠错**：更正人员、撤销 / 恢复误签、带来源的人工补记；唯一索引保证连点不重复。
- **请假与代班**：未来或进行中班次可指定代班；已结束旷班可补登记请假。无代班请假豁免缺勤，有代班时由指定人员签到。
- **加班与单次增员**：加班可自定义同日时段，签到或补记后计薪；正式班次可临时添加办公人员。
- **周班表（看板）**：Google Calendar 式连续周时间网格；绿色 = 到岗、红色 = 未到岗、灰色 = 未到班，自动定位当前时段。
- **工时与统计**：分别汇总常规、加班和总工时，以及请假、到岗率、迟到和未签到席位。
- **导入排班与成员**：支持三块布局排班 Excel 与成员信息 Excel 导入，随包提供空白模板，导入后留存源文件副本。
- **月报导出**：月报草稿自动保存、可编辑工作量与评分，一次导出工作报表、绩效考核表、工时记录表、排班表、工资考核表五类文件。
- **设置与更新**：可开关 Windows 登录自启动、选择手动/自动更新、配置目录并查看文件清单。
- **备份与恢复**：每日首次自动备份，逐份 SHA-256 完整性校验；支持立即备份、从列表恢复、从其他位置恢复，保留最近 30 份。
- **安全配置**：受控 IPC、上下文隔离的 Electron 安全配置；渲染进程不直接访问 Node、SQLite 或文件系统。

## 快速开始（安装版用户）

1. 从 **[Releases](https://github.com/diego20050818/network-service-checkin/releases)** 下载最新 `network-service-checkin-<版本>-x64.exe`。
2. 双击安装；安装时可选安装目录、是否创建桌面与开始菜单快捷方式。
3. **首次使用**：进入「排班与成员」页，下载随包提供的空白排班模板与人员信息模板，填写后导入正式排班和成员资料（应用会留存源文件副本）。
4. **每天**：打开软件，在「签到」首页勾选实际到场人员并签到即可。
5. **临时调整**：进入「请假与加班」办理请假、代班、单次办公增员或加班安排。
6. **月底**：进入「月报」页核对工时、填文字与评分，预览后选择导出目录，一次导出五类文件。

> 开发版（未打包）只显示自启动状态，不提供开关；安装版才可配置 Windows 登录自启动。

## 使用方法

### 1. 首次导入排班与成员

- 进入「**排班与成员**」页，下载「空白排班导入模板」和「空白人员信息模板」（随包内置）。
- 按模板的三块布局填写排班 Excel、成员信息 Excel。
- 点击导入；系统校验并记录来源，正式排班与实际签到分开保存，不会把旧的历史记录混入。排班单元格为空、待补或空缺时不生成席位，也不进入到岗、未到岗与工时统计。

### 2. 每日签到

- 打开应用，首页「**签到**」显示当天全部班次、负责人、当前状态与班次结束倒计时。
- **单人班**：默认选中原排班人，直接签到即可。
- **多人维修班**：勾选实际到场的席位，可替换到场人、补上空缺席位。
- 点击签到后显示真实打卡时刻与完整计薪工时；签到失败会保留当前选择，便于重试。
- **纠错**：在记录页可更正人员、撤销/恢复误签、人工补记。

### 3. 周班表（看板）

- 「**周班表**」展示负责人、办公人员、代班、请假和加班：**绿**=到岗、**红**=未到岗、**灰**=未到班、**黄**=请假。
- 看板、统计与导出共用同一汇总服务，数字一致。

### 4. 工时与统计

- 查看本月或自定义周期的成员工时汇总、签到明细、到岗率、迟到次数与已结束未签到席位。
- 宽松模式默认不判迟到；迟到模式晚于「开始 + 阈值」才标迟到，且**不扣工时**。
- 加班不参与到岗率、迟到或缺勤；只有签到或人工补记后才按完整计划时长计入加班与总工时。

### 5. 请假、加班与单次增员

- 在「**请假与加班**」选择日期。无代班请假不会计入到岗率分母；指定代班后，只能由该代班人签到。
- 已结束且未签到的班次可补登记无代班请假；已结束班次不能再指定代班人。
- 加班只支持同一自然日且结束时间晚于开始时间。历史加班先建立安排，再到「签到记录」人工补记。
- “添加办公人员”只影响当前所选的单次班次；有签到或请假的手工席位必须先撤销相关记录才能移除。

### 6. 月底月报导出

1. 选择所属年月与统计范围（默认上月 26 日到本月 25 日）。
2. 填写日期、工作文字、评分、推荐与备注；草稿停止输入后自动保存。
3. 预览结构与文件名（使用当前草稿与同一数据快照）。
4. 选择五类文件及本地输出目录：
   `工作报表(DOCX) · 绩效考核表(DOCX) · 工时记录表(XLSX) · 排班表(DOCX) · 工资考核表(DOCX)`。
5. 主进程创建唯一批次目录并生成文件，导出后重新校验占位符与文件结构（不残留 `[mouth]` 等占位符）。

### 7. 设置

- **Windows 登录自启动**：安装版可开关；开发版仅显示状态。
- **默认导出目录 / 备份目录**：通过系统目录选择器更改。
- 查看应用数据位置、当前有效排班文件、最近导入的员工文件与随包输出模板。
- **更新模式**：默认手动。自动模式仅在启动时检查一次并后台下载，下载完成后仍由用户确认“重启并安装”；开发版不启用更新服务。

### 8. 备份与恢复

- 应用**每天首次启动**自动创建一份备份；也可在「备份管理」立即备份。
- 列表逐份校验 SQLite 的 SHA-256 完整性，损坏备份不可恢复。
- 支持「从列表恢复」与「从其他位置恢复」；恢复前自动生成 `pre_restore` 安全备份。最多保留最近 30 份。

> 更详细的分步说明见 [功能手册与操作指南](#功能手册与操作指南)。

## 开发与构建

### 环境准备

- Node.js `≥ 24.18.0`；在 PowerShell 中使用 `npm.cmd`，避免系统执行策略拦截 `npm.ps1`。

### 安装依赖

```powershell
npm.cmd install
```

### 本地运行

```powershell
npm.cmd run dev
```

### 测试与质量门禁

```powershell
npm.cmd run verify        # typecheck + test + build
npm.cmd run typecheck
npm.cmd run test
npm.cmd run test:e2e      # 端到端
```

### 生成 Windows 安装包

```powershell
npm.cmd run package:win
```

输出到 `apps/desktop/release/`。模板通过 `electron-builder` 的 `extraResources` 随安装包分发；数据库与导入源文件副本写入 Electron `userData`，不写安装目录。

> 当前开发构建未配置代码签名证书，安装包 Authenticode 状态为 `NotSigned`。正式分发前建议使用组织证书签名。

## 版本与发布

版本遵循 **语义化版本**；当前为 `0.5.0`。发布流程：

1. `npm.cmd run verify` 通过全部门禁。
2. `npm.cmd run package:win` 生成 x64 NSIS 安装包。
3. 打标签并推送：

   ```powershell
   git tag -a v0.5.0 -m "v0.5.0"
   git push origin v0.5.0
   ```

4. 在 GitHub Release 同时上传 `.exe`、`.blockmap` 和 `latest.yml`，可选附带手册 PDF。

## Release 发布指南

发布新版本（以当前 `0.5.0` 为例）：

1. **门禁**：`npm.cmd run verify`（typecheck + test + build）全通过。
2. **打包**：`npm.cmd run package:win` 生成安装包、`.blockmap` 与 `latest.yml`，并校验元数据中的版本、文件名和 SHA-512。
3. **打标签并推送**：

   ```powershell
   git tag -a v0.5.0 -m "v0.5.0"
   git push origin v0.5.0
   ```

4. **建 Release**：标题使用 `v0.5.0`；附件必须带 `.exe`、`.blockmap` 与 `latest.yml`，否则客户端无法自动更新。

命令行方式（已登录 `gh`）：

```powershell
gh release create v0.5.0 -t "v0.5.0" -n "见 CHANGELOG.md" `
  "apps/desktop/release/network-service-checkin-0.5.0-x64.exe" `
  "apps/desktop/release/network-service-checkin-0.5.0-x64.exe.blockmap" `
  "apps/desktop/release/latest.yml"
```

> `v0.4.0` Release 没有 `latest.yml`，且 0.4.0 客户端没有更新器，所以需要手动安装一次 0.5.0。当前安装包仍为 `NotSigned`，可能触发 SmartScreen；代码签名不属于本版本已完成能力。
