# 设置与备份管理

## 设置入口

顶部“设置”页面集中显示和管理：

- Windows 登录自启动；开发版只显示状态，安装版允许开关。
- GitHub Release 更新模式；默认手动，自动模式启动检查并后台下载，安装前仍需确认重启。
- 应用数据目录和数据库文件位置，只允许查看与打开。
- 新月份月报的默认导出目录。
- 自动、手动和恢复前备份的存放目录。
- 当前有效排班源文件、最近导入的员工文件、随包导入模板和输出模板。

目录变更必须经过主进程的系统目录选择器。渲染进程只能打开应用数据、模板、已登记导出位置和当前配置的备份位置。

## 文件来源

排班和员工 Excel 导入后均复制到应用数据目录。排班来源记录在 `schedule_imports`，员工来源记录在 `member_imports`；设置页显示文件名、留存路径、导入时间、用途和文件是否仍存在。

从旧版升级的数据库没有旧员工文件来源记录时，设置页会提示重新导入；现有成员资料不会丢失。0.4.0 schema v2 数据和 manifest v2 备份可向前迁移到 0.5.x schema v3（0.5.1 相对 0.5.0 无 schema 变更）。

## 备份管理

应用每天首次启动自动创建一份备份，也支持手动备份。列表逐份读取 `manifest.json` 并校验 SQLite 文件 SHA-256，损坏备份不可恢复。每个备份包含：

- SQLite 安全快照；
- 排班源文件副本；
- 员工源文件副本；
- 当前版本输出模板副本。

当前备份目录最多保留最近 30 份。恢复前自动创建 `pre_restore` 备份，校验成功后替换数据库、补回源文件并重启应用。更换备份目录不会搬移旧备份，可通过“从其他位置恢复”读取旧目录。
