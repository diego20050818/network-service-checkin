# v0.6.0 发布与升级验证报告

验证日期：2026-09-08。状态：**已批准发布 v0.6.0 稳定版**。本次没有启动 NSIS 覆盖用户现用安装，没有修改现用 userData 数据库。

- 真实旧二进制生成数据的对账证据：[JSON](validation/v0.6.0-binary-upgrade.json)。这是隔离二进制升级测试，`installerExecution: false`。

### 旧程序与候选程序的升级测试

从本地保留的 **0.5.1 win-unpacked 实际程序**启动全新临时 userData，通过其原 API 创建成员（学号 `00001234`）、09:07–10:22 加班、人工补记及月报草稿。退出后确认数据库 schema 为 3。随后用 **0.6.0 打包后的实际 EXE**启动同一临时 userData。

候选 EXE 的 `app.isPackaged=true`、版本 `0.6.0`、更新器支持状态均已断言。启动后 schema 为 4；members、shifts、shift_slots、attendance_records、report_drafts 的每个原始列完全相等。升级备份中的数据库仍为 schema 3。现用安装的数据不参与测试。

该测试覆盖程序启动、打包资源、预迁移备份与真实旧程序数据兼容，**未执行 NSIS 安装向导、注册表升级或真实更新下载/重启安装**。

## 发布后继续补充的生产验收

1. 在可回滚的干净 Windows 验收机或虚拟机执行 0.4.0 手动覆盖安装、0.5.x 安装版更新到候选、卸载重装、更新保存握手和升级前备份回退。当前环境未提供 Windows Sandbox 命令，未代替用户在现用安装上执行这些步骤。
2. 在 Windows 125%/150% **系统显示缩放**下检查七个页面、原生文件对话框、中文输入法组合输入、键盘焦点与减少动态效果；补全日历创建/复制、成功拉伸、跨日移动及弹层边缘操作的人工流程。
3. 在真实数据副本及目标硬件上对账五类导出内容，并记录正常更新重启、冷启动和导出耗时。当前输出验收使用仓库模板与测试夹具，不能称为所有真实历史月报的逐文件一致性验收。
4. 依据组织分发要求完成签名/SmartScreen 检查，并最终核验候选哈希与批准发布的文件相同。未配置代码签名证书，当前包不宣称可信发行签名。

用户已明确批准按稳定版发布。以上项目仍保留为生产验收和后续签名工作的真实边界；0.5.x 能沿原更新器升级的契约已保留，但本报告不把它表述为已完成真实在线更新验收。
