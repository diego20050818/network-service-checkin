# ADR-003 v0.6.0 交互与数据边界

状态：已实现，发布候选验收中。依据为用户明确确认的 v0.6.0 方案及 `network_service_checkin_UIUX_20260908.pdf`；附件中的说明作为设计依据，不作为发布或修改其他系统的授权。

## 界面

Electron 保持 `cn.edu.networkservice.checkin`、既有 userData 目录及 GitHub latest 通道。渲染层仍启用隔离与沙箱，通过 preload 白名单调用主进程。

React Aria Components 负责控件、弹层、键盘焦点与中文输入过程；人员搜索的展示文本与提交 ID 分开。FullCalendar Standard 7.1.0 仅在 `CalendarPage` 适配时间网格与拖动事件，不引入 Premium 功能。工具栏及编辑抽屉复用统一控件。校徽源 SVG 本地打包，以 CSS mask 使用主题色，路径比例及素材来源保存在 assets 目录。

窗口由固定高度侧栏、固定页头和可滚动工作区组成。侧栏高度绑定窗口而非长页面内容；小窗口内侧栏可独立滚动。减少动态效果跟随系统偏好。

## 三种数据边界

1. 正式来源：`shift_sources` 保留旧班次来源快照，`formal_schedule_versions` 保留导入定义，Excel 归档继续作为正式排班 DOCX 的来源。
2. 执行安排：保留原 shifts/slots ID；单次修改带 expectedRevision、operationId，同日时段校验，拖动 15 分钟步进，表单精确到分钟。已有任何签到历史（含已撤销）或已经结束的安排锁定普通时间编辑。
3. 考勤与导出：考勤记录的 paid_minutes 不由普通计划编辑重算。更正、撤销、恢复仍走考勤服务；导出使用固定数据库副本、草稿版本和源文件副本。

## 命令与恢复

复合命令在一个 SQLite 事务中保存前后状态和结果。失败回滚；重复 operationId 重放已有结果，同一 ID 携带不同请求则拒绝。即时撤销提示停留 10 秒，悬停或聚焦暂停计时。历史仍留在数据库，最近操作显示 100 条；取消班次详情提供长期恢复入口，已撤销签到与移除席位可在详情恢复原 ID。

逆操作要求当前状态与原操作的后状态一致。后续修改时拒绝直接逆操作，由对应详情执行明确更正。统一命令区分写入失败和已保存但刷新失败；根工作区的业务刷新通知当前签到、日历、记录、统计、调整及月报预览。

## 草稿与导入

草稿会话移出页面，按月份独立、650ms 防抖、串行写入并检查 revision。离开页面、切月、正常关闭、更新安装及恢复重启之前等待保存；失败允许保留并重试、取消离开或明确放弃。预览在所有异步读取完成后复查请求顺序和业务版本，不能写回编辑草稿。

主进程解析用户选择的 Excel，返回受控预览标识、差异及冲突。应用复核文件哈希与业务数据版本。只匹配唯一明确的原始班次和成员；单次调整、历史、请假、缺失或不唯一的关系必须明确处理。历史不允许替换，同名成员必须先整理。预览不会改动执行数据；同一运行会话内已完成的预览可重放结果。

## 迁移与发布

schema v4 只追加列、来源快照、操作历史、数据版本和导出请求表。v2/v3 的所有原始列在复制数据库中逐项对账。升级前备份包含数据库及排班源、成员源、模板，带哈希验证；备份失败停止迁移，升级备份不参加每日备份轮换。

恢复先在临时副本迁移并检查完整性/外键，再建立当前数据的 pre_restore 备份、复制已验证归档和替换数据库。同名不同内容的归档拒绝覆盖。迁移失败保留原库与诊断信息。

发布候选的自动化证据、真正执行过的安装步骤和仍待人工检查的步骤必须分开记录。稳定更新只在安装版升级验收完成后发布。
