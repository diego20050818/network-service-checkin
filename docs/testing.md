# 测试与质量门禁

## 分层

- 领域测试：时间边界、重叠计薪、迟到阈值、评分封顶、文件命名。
- 服务集成测试：内存 SQLite 的事务与唯一约束、v1→v2 迁移、看板聚合、改错与恢复。
- 存储与备份测试：默认目录持久化、当前源文件清单、备份列表、数据库 SHA-256 完整性和恢复边界。
- 文件测试：生成 DOCX/XLSX 后重新打开、核对工作表/ZIP 结构、占位符和团队总量。
- E2E：构建后启动源码版与打包版 Electron，验证安全配置、空数据首页、主导航，以及设置页的开机自启动、文件位置和备份管理入口。
- 响应式 E2E：使用带到岗/未到岗/未到班夹具的数据，在 1100×700 检查今日议程、周时间网格、绩效编辑区和设置页，在 1440×900 检查工资工作量编辑区。
- 视觉检查：关键页面生成截图；周看板应是连续时间网格而非卡片列表，并自动滚到当前时段。
- 人工 Win10/11 门禁：真实排班、中文路径、缩放、冷启动、断网、无 Office/Node/Python、安装/升级/回滚。

## 命令

```powershell
npm.cmd run typecheck
npm.cmd run test
npm.cmd run build
npm.cmd run test:e2e
```

发布候选至少通过 `npm.cmd run verify`。E2E 和安装包测试必须在 Windows runner 或目标机执行。

## 未自动化门禁

性能目标（冷启动 5 秒、签到 1 秒、30 人月报 15 秒）必须记录实际硬件、数据量和耗时。当前仓库没有客户最新排班，也不能替代“未装开发环境的 Win10/11 实机”验收，因此不得把合成夹具测试表述为正式生产验收。
