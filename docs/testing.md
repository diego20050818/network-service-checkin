# 测试与质量门禁

v0.6.0 新增门禁和实际执行结果见 [升级验证报告](v0.6.0-upgrade-validation.md)。新版覆盖 schema v2/v3→v4、旧清单恢复、操作回滚、月报草稿串行保存、固定快照导出、日历交互及升级前备份。以下早期测试记录只描述原有基线。

## 分层

- 领域测试：时间边界、重叠计薪、迟到阈值、评分封顶、文件命名，以及请假、代班、单次增员和加班规则。
- 服务集成测试：内存 SQLite 的事务与唯一约束、v1→v2→v3 迁移、看板聚合、改错与恢复。
- 存储与备份测试：默认目录持久化、当前源文件清单、备份列表、数据库 SHA-256 完整性和恢复边界。
- 兼容性测试：从 v2 数据库迁移，并从 0.4.0 结构的 v2 备份恢复后自动迁移到 v3；备份清单保持 v2。
- 文件测试：生成 DOCX/XLSX 后重新打开，核对工作表/ZIP 结构、占位符和团队总量；加班写入成员工时块和“签到明细”，正式排班 DOCX 不包含加班或临时办公人员。
- 更新器测试：使用伪适配器覆盖检查、发现、下载进度、失败、下载完成和确认安装，不访问真实 GitHub。
- E2E：构建后启动源码版与打包版 Electron，验证安全配置、空数据首页、新导航、请假/增员/加班操作，以及设置页的更新模式、开机自启动、文件位置和备份管理入口。
- 响应式 E2E：使用带到岗/未到岗/未到班夹具的数据，在 1100×700 检查今日议程、周时间网格、新调整页和设置页，在 1440×900 检查绩效与工资工作量编辑区。
- 视觉检查：关键页面生成截图；周看板应是连续时间网格而非卡片列表，并自动滚到当前时段。
- 人工 Win10/11 门禁：真实排班、中文路径、缩放、冷启动、断网、无 Office/Node/Python、安装/升级/回滚。

## 命令

```powershell
npm.cmd run typecheck
npm.cmd run test
npm.cmd run build
npm.cmd run test:e2e
```

发布候选至少通过 `npm.cmd run verify`、`npm.cmd run test:e2e`、生产依赖审计和 Windows 打包。发布前还要核对安装包、`.blockmap` 与 `latest.yml` 的文件名、版本和 SHA-512。E2E 和安装包测试必须在 Windows runner 或目标机执行。

## 未自动化门禁

性能目标（冷启动 5 秒、签到 1 秒、30 人月报 15 秒）必须记录实际硬件、数据量和耗时。当前仓库没有客户最新排班，也不能替代“未装开发环境的 Win10/11 实机”验收，因此不得把合成夹具测试表述为正式生产验收。
